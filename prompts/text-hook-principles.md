## 목표

창업가가 자기 문제처럼 느끼고, 결론이 궁금해 스크롤을 멈추는 **두 줄짜리 텍스트 훅**을 만든다.
내용을 다 말하는 요약문이 아니라 `익숙한 전제 + 예상 밖의 빈틈`을 약속하되, 릴스가 실제로 답하는
범위 안에서만 호기심을 만든다.

## 두 줄 설계

1. 모든 생성 제목은 공백 제외 12~24자, 자연스럽게 띄어쓴 3어절 이상으로 쓴다. 모델 응답에는
   줄바꿈을 넣지 않고 한 줄로 직렬화한다. 렌더러가 두 줄로 나눠 표시한다.
2. 제목을 만들 때부터 **첫 줄은 대상·상황·통념**, **둘째 줄은 반전·위험·판단 기준·행동**이 되도록
   두 의미 덩어리로 설계한다. 첫 줄만 읽으면 다음 말이 궁금하고, 둘째 줄을 읽으면 영상에서 얻을
   효용이 보여야 한다.
3. 두 덩어리가 자연스러운 어절·구절 경계에서 갈리도록 쓴다. 첫 줄이 `그런데`, `이것`, `그 이유`처럼
   맥락 없는 낚시만 남거나, 둘째 줄이 첫 줄을 단순 반복하면 안 된다.
4. 창업가의 현실적인 관심사인 제품, 마케팅, 고객, 채용, 공동창업자, 성장, 실패, 생존, 의사결정 중
   실제 발화의 핵심과 맞는 소재를 앞세운다.

## 검증된 훅 유형

- **통념 반박형**: 널리 믿는 조언이나 상식을 문제 삼아 숨은 맹점을 연다.
  예: `1인 창업가들에게 / 가장 과대평가된 조언`
- **긍정→부정 반전형**: 첫 줄의 강점·성과를 둘째 줄의 실패·한계와 충돌시킨다.
  예: `마케팅은 훌륭한데 / 망하는 브랜드의 특징`, `완벽한 앱도 / 마케팅이 최악이면 끝이다`
- **우선순위 전복형**: 모두가 먼저 한다고 믿는 일보다 더 중요한 것을 예고한다.
  예: `제품을 만드는 것보다 / 훨씬 중요한 창업가의 자질`
- **판단 기준 공개형**: 어려운 선택에서 가장 먼저 볼 기준 하나를 약속한다.
  예: `공동창업자를 찾을 때 / 가장 먼저 봐야하는 것`
- **구체적 행동형**: 당장 실행할 수 있는 단호한 행동이나 좁은 목표를 제시한다.
  예: `미친듯이 만들어서 / 뭐라도 보여줘야 한다`, `고객 딱 100명만 / 확실히 만족시키자`
- **성공 경계형**: 좋은 결과가 커질수록 생기는 역설적인 위험을 예고한다.
  예: `창업자가 성공할수록 / 조심해야 하는 이유`

여러 후보를 만들 때는 후보끼리 다른 훅 유형을 사용한다. 실제 근거가 있다면 최소 하나는
통념 반박형, 긍정→부정 반전형, 우선순위 전복형 중에서 고른다. 같은 문장의 단어 순서만 바꾼
유사 후보는 만들지 않는다.

## 문장과 사실성

1. 스타카토로 끊고, 빼도 뜻이 같은 조사·수식어만 덜어낸다. `가장`, `훨씬`, `딱`, `완벽한` 같은 말은
   실제 순위·비교·수치·평가가 근거에 있을 때만 쓴다.
2. 명사구나 `특징`, `자질`, `조언`, `이유`, `기준`, `선택`처럼 답을 예고하는 말로 끝내는 형태를
   우선한다. 다만 실제 발화의 힘을 살리는 짧고 단호한 행동문·경고문은 허용한다.
3. 시청자가 모르는 브랜드명·제품명·전문용어는 뺀다. 꼭 필요하지 않은 회사 이름은 `첫 고객`,
   `직원 셋`, `공동창업자`처럼 누구나 바로 이해하는 말로 바꾼다.
4. 과장·허위·원문에 없는 숫자, 결과, 비교, 최상급은 금지한다. 특히 `100명`, `0원`, `가장`처럼
   클릭을 높이는 표현은 근거에 직접 있을 때만 사용한다.
5. 제목이 만든 질문이나 약속은 선택한 릴스 안에서 반드시 회수되어야 한다.

나쁜 예: `성공하는 방법을 알려드립니다` (긴장과 구체성이 없음),
`이것 때문에 모든 창업가가 망한다` (근거 없는 공포·최상급),
`Notion으로 온보딩 자동화` (낯선 제품명이 먼저 나오고 반전이 없음).
